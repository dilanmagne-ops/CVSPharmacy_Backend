02 · Fundamentos

Primero, ¿qué es un backend?

Es la parte de un sistema que recibe solicitudes, aplica reglas y consulta o modifica datos. La interfaz puede ser web, móvil o cualquier cliente que hable HTTP.

API

Un contrato de comunicación

La API expone direcciones (rutas) y métodos HTTP. Por ejemplo, GET /api/products pide una lista de productos.

JSON

Un formato de intercambio

El cliente envía o recibe objetos JSON. Es texto estructurado que representa datos de manera entendible para distintos lenguajes.

Persistencia

Datos que sobreviven

La base relacional almacena productos, lotes y proveedores en tablas relacionadas; no desaparecen al detener el servidor.

¿Qué es un repositorio?

Un componente que encapsula cómo se buscan y guardan entidades. El servicio solicita “buscar producto”; el repositorio traduce esa operación a consultas de base de datos.

¿Qué es inyección de dependencias?

ASP.NET construye los objetos y entrega sus dependencias. En Program.cs, AddScoped registra implementaciones que vivirán durante una solicitud HTTP.

05 · Modelo del negocio

¿Qué información conoce la farmacia?

Las entidades son los conceptos del negocio representados como clases y, normalmente, como tablas. Las relaciones permiten reconstruir el flujo de inventario.

Proveedor ──< OrdenCompra ──< DetalleOrdenCompra >── Producto
                                 │                       │
                                 ▼                       │
Recepcion ────────────────────< Lote >───────────────────┘
                                 │
                                 ├──< DetalleSalida >── SalidaInventario
                                 └──< SolicitudBaja

Usuario ── Rol

Producto

Código único, nombre, principio activo, presentación, unidad, precio, stock mínimo y estado. El stock se deriva de lotes válidos.

Lote

Vincula producto y recepción; contiene número, vencimiento, cantidad recibida y cantidad disponible. Permite controlar caducidad.

Proveedor

Identificación tributaria (NIT), razón social, contacto y estado. Puede relacionarse con órdenes de compra.

06 · API HTTP

Rutas disponibles en el código

Las rutas de productos usan /api/products y las de proveedores /api/suppliers. Los parámetros entre llaves se reemplazan por valores reales.

Método y rutaPropósitoRespuesta típica
GET /api/products?q=...&active=trueLista; filtro opcional por texto y estado.200 · colección en ApiResponse
GET /api/products/{id}Busca un producto por ID.200 o 404
GET /api/products/low-stockProductos con stock disponible menor o igual al mínimo.200 · colección
POST /api/productsCrea producto; valida datos y código único.201, 400 o 409
PUT /api/products/{id}Actualiza los datos editables del producto.200, 400, 404 o 409
PATCH /api/products/{id}/statusCambia solo el estado activo.200 o 404
GET /api/suppliers · GET /api/suppliers/{id}Lista proveedores o consulta uno.200 o 404
POST /api/suppliers · PUT /api/suppliers/{id}Crea o actualiza proveedor; valida NIT duplicado.201/200, 400, 404 o 409
PATCH /api/suppliers/{id}/statusCambia estado del proveedor.200 o 404
¿Qué significa el código? 200 = operación correcta · 201 = recurso creado · 400 = datos inválidos · 404 = registro inexistente · 409 = conflicto como código/NIT duplicado.
07 · Diseño de datos

Entidad, DTO y validación

No todo objeto que circula por la API debe ser una entidad de base de datos. Separar formas de entrada y salida protege el modelo y hace explícito el contrato.

Entidad

Representa el dominio persistente

Producto tiene relaciones con lotes y detalles de compra. Es lo que EF Core sigue y guarda.

DTO

Representa el mensaje de la API

GuardarProductoDto recibe campos editables. ProductoDto añade ID, fecha, stock calculado y alerta de stock crítico.

Reglas de entrada del producto

  • Código obligatorio, hasta 30 caracteres.
  • Nombre obligatorio, hasta 150 caracteres.
  • Presentación obligatoria, hasta 100 caracteres.
  • Unidad obligatoria, hasta 20 caracteres.
  • Precio no negativo, máximo 2 decimales.
  • Stock mínimo no negativo.

Mapeo y respuestas consistentes

AutoMapper convierte DTO ↔ entidad usando perfiles. ApiResponse<T> envuelve respuestas exitosas; resultados de servicio clasifican éxito, validación, ausencia o conflicto.

En HTTP esto facilita que el cliente sepa tanto qué ocurrió como qué datos recibió.

08 · Persistencia

Entity Framework Core y MySQL

EF Core es un ORM: traduce objetos C# y expresiones LINQ a operaciones SQL. El proveedor Pomelo conecta EF Core con MySQL.

DbContext: sesión con la base

FarmaciaDbContext expone DbSet para productos, lotes, proveedores, compras, usuarios y otros conceptos. Las configuraciones describen claves, columnas y relaciones.

Consulta segura por intención

El repositorio usa consultas asincrónicas y AsNoTracking cuando solo lee. Include carga lotes relacionados cuando el cálculo de stock los necesita.

// La aplicación configura MySQL al arrancar (Program.cs)
builder.Services.AddDbContext<FarmaciaDbContext>(options =>
  options.UseMySql(connectionString, ServerVersion.AutoDetect(connectionString)));

// Una consulta LINQ de lectura (idea simplificada)
context.Productos.Include(p => p.Lotes).AsNoTracking();

La conexión se obtiene de configuración con la clave ConnectionMySql. Para ejecutar, hace falta configurar un servidor y credenciales válidas localmente.

¿Por qué aparece stock cero? Registrar un producto crea el catálogo del producto, pero no una recepción de inventario. El stock se obtiene de lotes con fecha de vencimiento vigente y cantidad disponible positiva.
