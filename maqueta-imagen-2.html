Cómo leer el código, desde cero

Esta parte explica qué hace cada carpeta y archivo importante, cómo se relacionan las capas y por qué el proyecto está dividido. La idea principal: una petición entra por la API, atraviesa reglas de negocio y llega a MySQL por infraestructura.

¿Qué resuelve este backend?

Administra información de farmacia mediante una API HTTP. El código implementa operaciones de catálogo para productos y proveedores; también define entidades de compras e inventario para el modelo de datos.

Una petición es una conversación

El cliente envía un método, una ruta y, a veces, un cuerpo JSON. El servidor decide qué operación ejecutar y devuelve un estado HTTP y datos JSON.

Idea clave: separar el sistema en capas reduce el acoplamiento. Un controlador no necesita saber cómo se escribe SQL; un servicio no necesita conocer el formato de una respuesta HTTP.

Las cuatro capas: qué hace cada una

1. Api — la puerta HTTP

Los controladores reciben datos del usuario, leen parámetros de ruta o consulta, llaman al servicio y convierten el resultado en códigos como 200, 201, 400, 404 o 409.

No debería: contener consultas SQL ni reglas largas de negocio.

2. Services — el caso de uso

Organiza la operación de negocio: validar, verificar duplicados, buscar entidades, mapear, guardar y decidir si la acción tuvo éxito.

No debería: construir directamente respuestas HTTP.

3. Core — el lenguaje del negocio

Define qué es Producto, Proveedor, Lote, qué información se intercambia y qué operaciones prometen las interfaces.

No debería: depender de ASP.NET, EF Core o MySQL.

4. Infrastructure — los detalles técnicos

Implementa acceso a datos, claves, columnas, índices y mapeo entre objetos. Convierte operaciones de repositorio en consultas y cambios persistidos.

No debería: decidir el significado funcional de una regla de negocio.

Api/Program.cs: cómo arranca el servidor

Este archivo compone la aplicación. Registra dependencias primero, construye el servidor después y define el recorrido de cada solicitud.

var builder = WebApplication.CreateBuilder(args);

var connectionString = builder.Configuration.GetConnectionString("ConnectionMySql");
builder.Services.AddDbContext<FarmaciaDbContext>(options =>
    options.UseMySql(connectionString, ServerVersion.AutoDetect(connectionString)));

builder.Services.AddScoped<IProductoRepository, ProductoRepository>();
builder.Services.AddScoped<IProductoService, ProductoService>();
builder.Services.AddAutoMapper(typeof(ProductoProfile).Assembly);
builder.Services.AddControllers();
builder.Services.AddOpenApi();

var app = builder.Build();
if (app.Environment.IsDevelopment()) app.MapOpenApi();
app.UseHttpsRedirection();
app.UseAuthorization();
app.MapControllers();
app.Run();

Controladores: de la ruta al código

Controllers/ traduce HTTP a llamadas del sistema. Los atributos declaran rutas; los métodos expresan qué verbo acepta cada operación.

ProductoController.cs

[Route("api/products")] fija el prefijo. [HttpGet], [HttpPost], [HttpPut("{id:int}") ] y [HttpPatch("{id:int}/status") ] enlazan métodos HTTP con acciones.

  • GET colección: toma q y active desde la URL y llama al servicio.
  • GET por ID: devuelve DTO o 404.
  • GET low-stock: solicita productos con stock crítico.
  • POST: entrega un GuardarProductoDto al servicio; transforma éxito en 201 con CreatedAtAction.
  • PUT: actualiza un producto existente y responde 200, 400, 404 o 409 según el resultado.
  • PATCH status: cambia únicamente el estado activo.
  • Demostraciones: rutas demo/... comparan retorno sin DTO y armado manual del DTO; el bloque oficial usa servicios y AutoMapper.

ResponderError convierte estados del servicio en respuestas HTTP. Así el servicio habla en términos de negocio y el controlador habla en términos del protocolo HTTP.

ProveedorController.cs

Usa el prefijo api/suppliers. Expone listar, consultar por ID, crear, actualizar y cambiar estado. Valida DTO de alta/cambio de estado; si el NIT duplicado genera InvalidOperationException, responde 409 Conflict. Si no existe el registro, responde 404 Not Found.

Este controlador hace validación y manejo de excepciones directamente, mientras ProductoController delega más resultados tipados al servicio. Son estilos distintos que conviene unificar al evolucionar el proyecto.

Api/Response/ApiResponse.cs

ApiResponse<T> es un envoltorio genérico con una propiedad Data. El mismo formato puede transportar un DTO, una lista u otro tipo sin crear una clase de respuesta para cada operación.

public class ApiResponse<T>
{
    public T Data { get; set; }
    public ApiResponse(T data) => Data = data;
}

Services: las reglas y los casos de uso

ProductoService.cs — crear, consultar y cambiar producto

El constructor recibe un repositorio, un mapper y validadores. Eso permite sustituir las implementaciones y aislar las reglas.

Validar: llama a FluentValidation. Si hay errores, produce estado Validacion con campo y mensaje.
Comprobar unicidad: consulta si ya existe el código del producto.
Convertir: AutoMapper pasa de DTO de entrada a entidad Producto.
Persistir: el repositorio guarda y devuelve errores de clave duplicada como conflicto de negocio.
Responder: vuelve a consultar y transforma a DTO de salida con stock calculado.

El listado aplica filtros por texto y estado; el caso de stock crítico delega la consulta al repositorio. La actualización recupera una entidad rastreada, verifica que el código no pertenezca a otro ID, copia campos permitidos y guarda.

Regla contra duplicados: se revisa primero en el servicio para dar un mensaje claro y también se protege con un índice único en MySQL para cubrir dos solicitudes simultáneas.
ProveedorService.cs — proveedores

Recupera datos por repositorio, convierte con AutoMapper, normaliza el NIT y evita duplicados. Al crear fija Activo = true; al actualizar excluye el ID actual al revisar si el NIT pertenece a otro proveedor. Usa SaveAsync para confirmar cambios.

null significa que no se encontró el proveedor en búsquedas o actualización; el controlador lo convierte en 404.

¿Por qué async/await?

Las consultas de base de datos esperan I/O (red/disco). Los métodos async Task<T> liberan el hilo mientras espera la respuesta, para que el servidor atienda otras solicitudes. await retoma el método cuando termina la operación.

Core: entidades, DTO y contratos

Entities/ — objetos del dominio

Producto y Proveedor contienen campos persistentes y propiedades de navegación. Por ejemplo, Producto se relaciona con Lotes y DetalleOrdenCompra; Proveedor con OrdenesCompra.

Las clases de Lote, OrdenesCompra, Recepcion, SalidasInventario, DetalleSalida, SolicitudesBaja, Usuario y Rol amplían el modelo de farmacia.

DTOs/ — contrato de datos

GuardarProductoDto incluye los campos editables, no el ID ni el stock calculado. ProductoDto sirve para lectura e incluye stock y alerta. Para proveedor hay DTO de guardar, lectura y cambio de estado.

Separarlos evita exponer propiedades internas y deja controlar exactamente qué puede enviar el cliente.

Interfaces/ — promesas del sistema

IProductoService declara casos de uso y IProductoRepository declara operaciones de datos. Sus implementaciones están en Services e Infrastructure.

Una interfaz permite depender de la capacidad requerida, no de una clase concreta: esto facilita pruebas y cambios técnicos.

Results/ y Exceptions/

ResultadoServicio<T> expresa Exito, Validacion, NoEncontrado o Conflicto con datos y errores. CodigoProductoDuplicadoException traduce un duplicado detectado durante escritura.

Las excepciones son para fallos excepcionales; los resultados tipados representan desenlaces esperables del caso de uso.

public class Producto
{
    public int Id { get; set; }                    // clave del registro
    public string Codigo { get; set; } = null!;   // código de catálogo
    public decimal PrecioVenta { get; set; }       // tipo decimal para dinero
    public virtual ICollection<Lote> Lotes { get; set; } = new List<Lote>();
}

virtual ICollection expresa una relación uno-a-muchos y permite que EF Core cargue colecciones relacionadas según la consulta. string? indica que el valor puede ser nulo; null! suprime una advertencia del compilador cuando el dato lo suministrará el sistema/base.

Infrastructure: cómo se habla con MySQL

FarmaciaDbContext.cs — sesión y tablas

DbContext representa una unidad de trabajo con la base. Cada DbSet<Entidad> ofrece una entrada tipada a una tabla; OnModelCreating aplica las configuraciones de todas las entidades del ensamblado y fija caracteres/collation.

Cuando se llama a SaveChangesAsync, EF Core detecta altas/cambios y genera SQL para confirmarlos.

Data/Configurations/ — esquema explícito

Una clase por entidad implementa IEntityTypeConfiguration<T>. Define nombre de tabla y columnas, clave primaria, longitud, precisión, valores por defecto e índices únicos. Por ejemplo, Producto.Codigo y Proveedor.Nit son únicos; precio usa precisión 10,2.

Separar la configuración del modelo mantiene las clases de entidad legibles y concentra las decisiones del esquema.

Repositories/ — consultas y escritura

ProductoRepository compone LINQ con EF: Where filtra, FirstOrDefaultAsync busca uno, Include carga lotes, AsNoTracking optimiza lecturas sin edición y SaveChangesAsync persiste.

ProveedorRepository implementa búsquedas, detección de NIT duplicado y guardado. Los repositorios esconden los detalles de EF ante los servicios.

Mappings/ — AutoMapper

ProductoProfile define Entity → ProductoDto y GuardarProductoDto → Entity. Ignora ID, fechas y relaciones al escribir; calcula stock a partir de lotes con vencimiento vigente y cantidad positiva.

ProveedorProfile normaliza espacios, convierte textos opcionales vacíos en null y presenta Activo nulo como falso en lectura.

¿Por qué AsNoTracking? En una consulta de solo lectura, EF no necesita vigilar cambios del objeto. Reduce trabajo de memoria. Para actualizar, el repositorio obtiene una entidad rastreada y luego la guarda.

Validación, mapeo y manejo de errores

FluentValidation

Las clases Validator expresan restricciones como reglas legibles: obligatorio, longitud máxima, precio no negativo, correo con formato válido y estado presente. Centralizar reglas evita repetirlas en cada controlador.

AutoMapper

Los perfiles declaran conversiones entre tipos. Facilitan copiar campos con nombres coincidentes y reservar reglas especiales para propiedades calculadas o normalización.

ResultadoServicio<T>

El servicio devuelve un resultado de negocio. El controlador elige la respuesta HTTP: Validacion → 400, NoEncontrado → 404, Conflicto → 409, Exito → 200 o 201.

Restricción en dos niveles

El validator da mensajes claros al usuario; la base protege integridad con índices únicos y restricciones del esquema. Ambas capas importan porque varias solicitudes pueden llegar a la vez.

Tipos HTTP usados: GET consulta · POST crea · PUT reemplaza/actualiza datos · PATCH cambia parcialmente un recurso · 200 correcto · 201 creado · 400 entrada inválida · 404 no encontrado · 409 conflicto.

Ejemplo completo: crear un producto

Esta historia une carpetas y conceptos. El usuario envía datos; el servidor valida, guarda y responde.

HTTP: el cliente envía POST /api/products con un JSON que ASP.NET convierte a GuardarProductoDto.
Controller: ProductoController.InsertProducto llama a IProductoService.CrearProductoAsync.
Service: valida campos con el validator, busca duplicado y convierte el DTO a la entidad con AutoMapper.
Repository: añade Producto al DbSet y EF Core ejecuta SaveChangesAsync en MySQL.
Service de nuevo: recupera el registro para obtener relaciones y mapea a ProductoDto.
Controller: envuelve los datos en ApiResponse<ProductoDto> y responde 201 Created con la ubicación del recurso.

    [Route("api/products")]
    [ApiController]
    public class ProductoController : ControllerBase
    {
        private readonly IProductoRepository _productoRepository;
        private readonly IMapper _mapper;
        private readonly GuardarProductoDtoValidator _validator;
        private readonly IProductoService _productoService;
        private IActionResult? ResponderError<T>(ResultadoServicio<T> resultado)
        {
            switch (resultado.Estado)
            {
                case EstadoResultado.Validacion:
                    return BadRequest(new
                    {
                        message = resultado.Mensaje,
                        errors = resultado.Errores.Select(e => new
                        {
                            field = e.Campo,
                            error = e.Mensaje
                        })
                    });

                case EstadoResultado.NoEncontrado:
                    return NotFound(new
                    {
                        message = resultado.Mensaje
                    });

                case EstadoResultado.Conflicto:
                    return Conflict(new
                    {
                        message = resultado.Mensaje
                    });

                default:
                    return null;
            }
        }
        public ProductoController(
            IProductoRepository productoRepository,
            IProductoService productoService,
            IMapper mapper,
            GuardarProductoDtoValidator validator)
        {
            _productoRepository = productoRepository;
            _productoService = productoService;
            _mapper = mapper;
            _validator = validator;
        }

        public async Task<IActionResult> GetProductoSinDto(string codigo)
        {
            var producto = await _productoRepository

        // GET: api/products/demo/dto/5
        [HttpGet("demo/dto/{id:int}")]
        public async Task<IActionResult> GetProductoDto(int id)
        {
            var producto = await _productoRepository
                .GetProductoByIdAsync(id);

            if (producto == null)
                return NotFound("Producto no encontrado.");

            DateOnly hoy = DateOnly.FromDateTime(DateTime.Today);

            int stock = producto.Lotes
                .Where(l => l.FechaVencimiento >= hoy
                         && l.CantidadDisponible > 0)
                .Sum(l => l.CantidadDisponible);

            var productoDto = new ProductoDto
            {
                Id = producto.Id,
                Codigo = producto.Codigo,
                Nombre = producto.Nombre,
                PrincipioActivo = producto.PrincipioActivo,
                Presentacion = producto.Presentacion,
                UnidadMedida = producto.UnidadMedida,
                PrecioVenta = producto.PrecioVenta,
                StockMinimo = producto.StockMinimo,
                Activo = producto.Activo,
                CreadoEn = producto.CreadoEn,
                StockDisponible = stock,
                EsStockCritico = stock <= producto.StockMinimo
            };

            return Ok(productoDto);
        }
        #endregion

        // POST: api/products

        [HttpPost]
        public async Task<IActionResult> InsertProducto([FromBody] GuardarProductoDto productoDto)
        {
            var resultado = await _productoService.CrearProductoAsync(productoDto);
            var error = ResponderError(resultado);
            if (error != null)
            {
                return error;
            }
            var response = new ApiResponse<ProductoDto>(resultado.Data!);
            return CreatedAtAction(
                nameof(GetProductoById),
                new { id = resultado.Data!.Id },
                response);
        }


        // PUT: api/products/5

        [HttpPut("{id:int}")]
        public async Task<IActionResult> UpdateProducto(
            int id,
            [FromBody] GuardarProductoDto productoDto)
        {
            var resultado = await _productoService
                .ActualizarProductoAsync(id, productoDto);

            var error = ResponderError(resultado);

            if (error != null)
            {
                return error;
            }

            var response = new ApiResponse<ProductoDto>(resultado.Data!);

            return Ok(response);
        }


        // PATCH: api/products/5/status

        public async Task<IActionResult> CambiarEstadoProducto(int id, [FromBody] CambiarEstadoProductoDto estadoDto)

            if (error != null)
            {
                return error;
            }
            var response = new ApiResponse<object>(new
            {
                message = "Estado actualizado correctamente.",
                id = id,
                activo = resultado.Data
            });
            return Ok(response);
        }

    [HttpGet]
    public async Task<IActionResult> GetAll()
    {
        var proveedores = await _proveedorService.GetAllAsync();
        return Ok(new ApiResponse<IReadOnlyList<ProveedorDto>>(proveedores));
    }

    [HttpGet("{id:int}")]
    public async Task<IActionResult> GetById(int id)
    {
        var proveedor = await _proveedorService.GetByIdAsync(id);
        return proveedor is null
            ? NotFound(new { message = "Proveedor no encontrado." })
            : Ok(new ApiResponse<ProveedorDto>(proveedor));
    }

    [HttpPost]
    public async Task<IActionResult> Create([FromBody] GuardarProveedorDto proveedorDto)
    {
        var validation = await _validator.ValidateAsync(proveedorDto);
        if (!validation.IsValid)
            return BadRequest(new
            {
                message = "Error de validación.",
                errors = validation.Errors.Select(error => new
                {
                    field = error.PropertyName,
                    error = error.ErrorMessage
                })
            });

        try
        {
            var proveedor = await _proveedorService.CreateAsync(proveedorDto);
            return CreatedAtAction(nameof(GetById), new { id = proveedor.Id },
                new ApiResponse<ProveedorDto>(proveedor));
        }
        catch (InvalidOperationException ex)
        {
            return Conflict(new { message = ex.Message });
        }
    }

    [HttpPut("{id:int}")]
    public async Task<IActionResult> Update(int id, [FromBody] GuardarProveedorDto proveedorDto)
    {
        var validation = await _validator.ValidateAsync(proveedorDto);
        if (!validation.IsValid)
            return BadRequest(new
            {
                message = "Error de validación.",
                errors = validation.Errors.Select(error => new

                    error = error.ErrorMessage
                })
            });

        {

                : Ok(new ApiResponse<ProveedorDto>(proveedor));
        }

        }
    }

    [HttpPatch("{id:int}/status")]

                    Errores = validacion.Errors.Select(error => new ErrorCampo

                        Mensaje = error.ErrorMessage
                    }).ToList()
                };
            }

            var producto = await _productoRepository
                .GetProductoParaActualizarAsync(id);

            if (producto == null)
            {
                return new ResultadoServicio<bool>
                {
                    Estado = EstadoResultado.NoEncontrado,
                    Mensaje = "Producto no encontrado."
                };
            }

            producto.Activo = estadoDto.Activo!.Value;

            await _productoRepository.UpdateProducto(producto);

            {
                Estado = EstadoResultado.Exito,
                Data = producto.Activo == true
            };
